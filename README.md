# stt-thing

Живые субтитры собеседника поверх всех окон, с переводом. Звук звонка идёт через
[BlackHole](https://github.com/ExistentialAudio/BlackHole), распознаёт
`sonic-speech/parakeet-tdt-0.6b-v3-int8` на MLX (Apple Silicon, 25 европейских
языков, ~0.9 ГБ памяти), перевод делает `gemini-3.5-flash-lite` (minimal thinking)
через OpenRouter или свой OpenAI-совместимый эндпоинт.

```
BlackHole ──► backend/stt_server.py ──JSON lines──► mac/ (Swift)
              VAD + parakeet-mlx + LocalAgreement      плашка оригинала
                                                       плашка перевода ──► LLM
```

## Запуск

Нужны macOS 14+, Apple Silicon, [uv](https://docs.astral.sh/uv/), Xcode.

```bash
cd backend && uv sync          # один раз; модель (~0.8 ГБ) скачается при первом запуске
cd ../mac && ./make-app.sh     # собирает mac/build/STT Thing.app
open "mac/build/STT Thing.app"
```

При первом запуске macOS спросит доступ к микрофону - он нужен для чтения любого
входа, включая BlackHole.

Для отладки можно запустить бинарник из терминала - логи бэкенда пойдут в stderr:

```bash
cd mac && swift run
```

## Перевод и расходы

- Меню → "Translation settings…" (⌘,): включить перевод, языки "с" и "на",
  провайдер.
  - **OpenRouter** (по умолчанию): нужен только ключ. Модель зашита:
    `google/gemini-3.5-flash-lite`, `reasoning.effort: minimal`.
  - **Custom (OpenAI API)**: любой `{Base URL}/chat/completions`. По умолчанию
    стоит vertex-proxy (`…run.app/v1`, модель `gemini-3.5-flash-lite`,
    `reasoning_effort: minimal`); кнопка "From vertex-proxy" берёт ключ из
    `~/.config/vertex-proxy/key`. Кнопка "Test" шлёт одну фразу и показывает
    ответ, задержку и цену.
- Ключи хранятся в Keychain. После пересборки приложения macOS может один раз
  спросить доступ к ним - это нормально для ad-hoc подписи.
- Переводится подтверждённый текст по предложениям: предложение уходит, как только
  после его точки подтвердилось следующее слово; длинная фраза без точек режется по
  запятой; конец сегмента уходит целиком. Для связности модель видит два
  предыдущих предложения.
- Перевод - в своей плашке (синяя, бейдж "EN → RU"), оригинал - в своей (серая).
  Двигаются и меняют размер отдельно. "Show original panel" прячет оригинал.
- Цена разговора - справа в полоске плашки перевода. Берётся `usage.cost` из
  ответа (его отдают и OpenRouter, и vertex-proxy), иначе считается по ценам
  токенов из настроек ($0.30 / $2.50 за 1M по умолчанию).
- Меню → "Cost & stats…": траты за разговор, сегодня и всего; график роста цены
  за разговор; траты по дням за 14 дней; таблица разговоров. "New conversation"
  обнуляет счётчик разговора. Данные - в
  `~/Library/Application Support/STT Thing/usage.jsonl`.

## Управление

- Плашки пропускают клики насквозь, к окну под ними. Ловит мышь только верхняя
  полоска: за неё плашку и перетаскивают.
- ⏸ в верхней полоске - пауза: начатая фраза дописывается, дальше звук
  игнорируется (модель остаётся в памяти, продолжение мгновенное). На паузе рамка
  жёлтая, текст можно листать колёсиком. ▶ - снова слушаем, плашка прокручивается
  к концу и опять пропускает клики. Из скрипта паузу переключает
  `kill -USR1 $(pgrep -f "STT Thing.app/Contents/MacOS/STTThing")`.
- `•••` в полоске, правый клик по полоске или `STT` в строке меню открывают меню:
  вход, пауза, размер текста, прозрачность, очистка, перезапуск бэкенда.
- `⌥⌘T` - показать или спрятать плашки.
- "Hide from screen sharing" (включено по умолчанию) просит macOS не показывать
  плашку при демонстрации экрана. Новые API захвата экрана могут это игнорировать,
  поэтому перед собесом проверь на своём Zoom/Meet.
- Размер плашки меняется за края, но только на паузе: в живом режиме края тоже
  пропускают клики.

## Как работает бэкенд

`backend/stt_server.py`:

1. Звук со входа → моно 16 кГц → WebRTC VAD. Речь началась - открываем сегмент
   (плюс 0.3 с до начала речи). Тишина 0.7 с - сегмент закрыт, финальный прогон.
2. Пока идёт речь, не чаще раза в 250 мс прогоняем окно сегмента через parakeet.
   Модель отдаёт слова с таймкодами.
3. `backend/agreement.py` - LocalAgreement-2 по словам: слово подтверждено, если две
   гипотезы подряд согласны в нём. Последнее согласованное слово ждёт, пока
   согласуется следующее или пройдёт 0.4 с, иначе ловим недоговорённое слово
   ("watch" вместо "walk me").
4. Окно больше 12 с - обрезаем по концу подтверждённого слова (лучше по концу
   предложения), оставляем ~5 с. Так каждый прогон стоит ~150-250 мс, даже если
   собеседник говорит минуту без пауз.

Подтверждённый текст - белый, черновой хвост - серый, прошлые фразы - приглушённые.

Полезные флаги (`python stt_server.py --help`): `--device`, `--silence`,
`--interval`, `--vad-mode`, `--list-devices`, `--file test.wav` (прогон файла в
реальном времени без BlackHole).

Команды в stdin бэкенда, по одной на строку: `pause`, `resume`.

Модель: `--model` (по умолчанию `sonic-speech/parakeet-tdt-0.6b-v3-int8`; parakeet-mlx
не умеет грузить квантованные веса, поэтому `load_parakeet` квантует слои сам, как
telegram-скилл). Окно 15 с декодируется за ~285 мс, пик памяти процесса ~0.9 ГБ
(у bf16 v2 было ~2 ГБ).

На тестовом аудио (TTS с британским, индийским и австралийским акцентом, 45 с)
через BlackHole: декод в среднем ~160 мс, подтверждённый текст отстаёт от звука на
~0.5 с (медиана).
